# Contributing

## Author Identity

For this repository, the sole author identity should appear as:

`Arun Malve <arundilse@gmail.com>`

Do not add AI or third-party co-author trailers, and do not use alternate
author display names for commits intended for this repository.

This repository is currently maintained as a **curated learning resource**
by a single author. Feel free to star, fork, and use the material for
learning — that's exactly what it's for.

**External content contributions (pull requests adding or changing
content) are not currently being accepted.** This isn't a judgment on
potential contributors — it's a deliberate choice to keep the upstream
repository's content, tone, and technical accuracy under single-author
control while it's actively being built out. See
[`docs/repository-governance.md`](docs/repository-governance.md) for how
that's enforced at the repository-settings level, and
[`docs/licensing-options.md`](docs/licensing-options.md) for the
distinction between "you can't push to this repo" and "you can do whatever
you want in your own fork" (forking and modifying your own copy is
explicitly fine and encouraged for personal learning notebooks).

## Reporting a technical issue

If you find a factual error, a broken command, an outdated tooling
reference, or a broken link, please **open an Issue** describing it —
that's welcome and helpful. Use the "Report Technical Issue" issue
template. Reporting an issue doesn't make you a contributor in the
authorship sense; the maintainer decides whether and how the content
changes in response.

Please don't open pull requests with content changes — they won't be
merged under the current policy, and it's a better use of your time to
file an Issue instead so the report doesn't get lost.

## If this policy changes

If external contributions open up in the future, this file will be
updated with the actual process (fork → branch → PR requirements →
review). Until then, the policy above is the current state.
